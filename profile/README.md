# Conecta Nexus

Organización con todos los repositorios y github project del proyecto académico.

## ¿Qué es?

Conecta Nexus es un proyecto académico para el curso de Desarrollo de Aplicaciones basadas en Microservicios 2026-II, el cual busca ofrecer problemáticas/proyectos de PYMEs reales de la región de cúcuta, a los estudiantes de ingeniería de sistemas de la UFPS a partir de su sexto semestre. El objetivo es que la plataforma ofreza registro de estudiantes o empresas, que empresas postulen sus problemáticas o necesitadades, y que los estudiantes puedan conectar con esas empresas para así llevar un proyecto por todo un semestre académico para materias que requieran este tipo de desarrollos.

## ¿Cómo ejecutar el proyecto?

Ir al repositorio de entrada para más información sobre ejecución: (conecta-nexus)[https://github.com/conecta-nexus/conecta-nexus]

## ¿Qué hay en esta organización?

Se cuenta con todos los repositorios respectivos para los microservicios (6 repos en total), un repo para frontend, un repo de gateway y otro para infraestructura en gcp con terraform. También se cuentan con un repositorio que se utilizó únicamente para el piloto del vídeo de entrega como material para el primer previo evaluado, un repositorio de un artículo de estado del arte para otro curso académico, y por último un repositorio especial para organizaciones donde se encuentra este README.

También se cuenta con un project a nivel de organización con el que se sigue el desarrollo de los Sprints a través de todos los repositorios (el repo (conecta-nexus)[https://github.com/conecta-nexus/conecta-nexus] tiene csvs y scripts con información para el manejo de los issues, workflows, y demás detalles para hacer manejo de esto)

### ¿Qué hay en el project?

Vistas de Kanban con columnas de to do, in progress, in review y done, administradas dinámicamente con workflows que se manejan a través de issues (con labels) y PRs. Hay secciones donde se proveen las historias de usuario, las tasks del equipo, overview de la siguiente iteración, vista de backlog completa, cronograma/roadmap a través del tiempo para los sprints, y unas secciones de gráficas en el apartado `insights` con task burn-up (por sprint) y user story status (todos los sprints).
